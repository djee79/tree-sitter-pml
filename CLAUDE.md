# tree-sitter-pml

Tree-sitter grammar for AVEVA PML2 (Programmable Macro Language). Consumed by
`pml-lsp` (Rust, via the `tree-sitter-pml` crate in `bindings/rust`) and by
Neovim through nvim-treesitter.

## Rules

- The parser name is `pml`. The C symbol is `tree_sitter_pml`. Do not rename.
- After **any** change to `grammar.js`, run `tree-sitter generate && tree-sitter test`
  and commit the regenerated `src/`.
- Never hand-edit anything under `src/` except `src/scanner.c`, the external
  scanner that emits the `_newline` token. Everything else there is generated.
- Every new construct gets a corpus test in `test/corpus/*.txt`. Use
  `tree-sitter test --update` to fill expectations, then review the diff.
- Keep `queries/*.scm` using nvim-treesitter capture names
  (`@function.method.call`, `@variable.member`, `@keyword.repeat`, ...).
  Folds capture whole nodes, not keyword tokens. Order patterns generic first,
  specific last: both Neovim and the tree-sitter CLI keep the last match. In a
  pattern with two captures on one node, the CLI keeps the last capture, so
  write `(comment) @spell @comment`.
- `test/highlight/basics.pml` asserts exact capture names (`-- <- name` and
  `-- ^ name` comments). Update it when captures change; `tree-sitter test`
  runs it.
- CI (`.github/workflows/ci.yml`) fails if `src/` is not regenerated.
- Bindings and build files (`package.json`, `Cargo.toml`, `bindings/`, ...) are
  generated by `tree-sitter init --update` from `tree-sitter.json`. Edit
  `tree-sitter.json`, then regenerate, rather than editing them by hand. The
  exception is the query constants enabled in `bindings/rust/lib.rs` and
  `bindings/python/tree_sitter_pml/__init__.py`.

## Layout

- `grammar.js` — the grammar. Precedence table `PREC` at the top.
- `src/scanner.c` — external scanner: one `_newline` per logical line,
  swallows `$` continuations, synthesizes a newline at EOF.
- `queries/` — highlights, folds, locals, injections.
- `test/corpus/` — one file per topic (control_flow, expressions, operators, ...).
- `test/highlight/` — highlight assertions.
- `src/` — generated parser, committed.

## Grammar notes

- Keywords are case-insensitive regex tokens extracted from `identifier`
  through the `word` rule. Never give keywords lexical precedence over
  `identifier`: tree-sitter lets precedence beat match length, so `equi`
  would lex as `eq` + `ui`.
- `type_identifier` is an alias of `identifier`, because `word` forbids a
  second token with the same regex.
- Every statement ends with `$._newline`. Blocks are `body($)`, which is
  statements and blank lines. The grammar has no GLR conflicts; keep it that
  way.
- Lines that start with a bare identifier, `$X` directive or `/ELEMENT` are
  `command_statement` (the PML1 command sub-language). A command's first
  argument cannot be a bare `(`, so `foo(1)` is always a function call.
- On a trailing-junk line like `!x = !a wrt /*`, tree-sitter recovers by
  inserting a missing `_newline` and parses the tail as a command. The CLI
  does not report this as an error; pml-lsp should check `is_missing()` too.
- Forms: `setup form`/`layout form` and `frame`/`view`/`alpha view`/`menu`/
  `bar` are `exit`-terminated blocks. Their bodies use `_form_statement`,
  which is `_statement` minus `exit_statement`, so `exit` always closes the
  innermost block. If a gadget type turns out not to be a block, remove it
  from `frame_block`.
- `expression` is a visible wrapper node; pml-lsp depends on that shape.

## Local Neovim setup (this machine)

`~/.local/share/nvim/site/parser/pml.so` is a symlink to `pml.so` built in
this repo with `tree-sitter build -o pml.so`; rebuild it after `generate`.
`~/.config/nvim/queries/pml/*.scm` are symlinks into `queries/`. The plugin
spec is `~/.config/nvim/lua/plugins/treesitter-pml.lua`.
